### layout

#### AspectRatio

Constrains its content to a fixed width-to-height ratio using the modern CSS `aspect-ratio` property. Media placed inside — an image, video, or iframe — fills the box and is cropped with `object-cover`, so thumbnails, preview tiles, map embeds, and chart frames keep a consistent shape across a…

- **Do:** Wrap media whose intrinsic dimensions vary (user uploads, remote thumbnails, map tiles) so a grid stays visually even; Reserve space for content that loads later (embeds, charts) to prevent layout shift
- **Don't:** Text blocks or components that should size to their own content — it will clip them; Reach for an arbitrary ratio outside the curated set; if a new ratio is genuinely needed, add it to the named map rather than opening a style hatch
- **Exports:** AspectRatio

#### Box

The lowest-level layout primitive in AEGIS. `Box` renders a `div` by default but is fully polymorphic through Base UI's `useRender`, so it can become any element or compose with another component via the `render` prop. It applies no styling of its own — it exists to be the single, consistent…

- **Do:** Reach for `Box` when you need a neutral, polymorphic wrapper and want a `data-slot` hook for targeting; The `render` prop to change the tag (`<section>`, `<ul>`, `<nav>`) or to merge props onto a child component instead of adding a wrapper `div`
- **Don't:** Try to pass `className`/`style` to `Box` — its API is closed. Put the token utilities on the element you hand to `render`, or reach for `Stack`/`Grid`/ `Container` for token-driven layout; `Box` where a more specific primitive (`Stack`, `Grid`, `Container`) already expresses the intent
- **Exports:** Box

#### Container

A max-width, horizontally-centered content wrapper built on the `Box` primitive. `Container` constrains a page or section to a readable measure and applies responsive horizontal gutters. The `size` variant picks the max width; `gutter` sets the padding.

- **Do:** Wrap page sections in a `Container` to keep content centered and within a comfortable width on large screens; `size="prose"` for long-form reading and `size="2xl"` for wide app dashboards
- **Don't:** `Container` for internal component spacing — that belongs to `Stack`/`Grid`; Nest containers; apply one per page section
- **Exports:** Container, containerVariants

#### Divider

A thin rule that separates content along the horizontal or vertical axis, with an optional inline label. Built on the Base UI `Separator` primitive so it emits the correct `role="separator"` and `aria-orientation` for assistive technology. All color comes from AEGIS border tokens.

- **Do:** Group related content — between list rows, toolbar clusters, or card sections; A labeled horizontal divider (e.g. "OR") to split alternative flows
- **Don't:** A divider where whitespace or a heading already communicates the break; over-ruling adds visual noise; Place interactive content inside a divider
- **Exports:** Divider, dividerVariants

#### Grid

A two-dimensional CSS-grid layout wrapper built on the `Box` primitive. `Grid` exposes a fixed `cols` count and a token-driven `gap`, plus `flow` for auto-placement and `align` for cross-axis alignment. Like every layout primitive it is a closed API — there is no public `className`/`style`; layout…

- **Do:** `Grid` for card galleries, metric tiles, dashboards, and any layout that needs alignment across both rows and columns; Combine `cols={12}` with `col-span-*` on children for classic 12-column layouts
- **Don't:** `Grid` for a single axis of evenly-spaced items — use `Stack`
- **Exports:** Grid, gridVariants

#### Masonry

A masonry layout — items flow into balanced vertical columns with no fixed row heights, so cards of varying height pack tightly (galleries, dashboards, card walls). Built on native CSS multi-column, so it degrades gracefully and needs no measurement JS.

- **Do:** Card walls, image galleries, and heterogeneous-height content; Pass a `columns` target; it steps down responsively
- **Don't:** Strict row alignment matters — that is Grid. Note that multi-column order flows top-to-bottom, then across
- **Exports:** Masonry

#### ResizablePanels

Two panels separated by a draggable divider — a split view (sidebar + content, editor + preview) the user can resize by pointer or keyboard. The divider is a proper `role="separator"` with `aria-valuenow/min/max`, works horizontally or vertically, and is RTL-aware.

- **Do:** Two-region split views a user should be able to resize; Pass exactly two children (start, end); Set `min` / `max` to protect each panel's usable space
- **Don't:** More than two regions (nest instead) or for non-resizable layout — that is Grid / Stack
- **Exports:** ResizablePanels

#### ScrollArea

A scrollable container with thin, theme-aware overlay scrollbars that match the AEGIS surface. Built on the Base UI ScrollArea primitive, so native scrolling physics, keyboard scrolling, and accessibility are preserved while the browser's default scrollbar is replaced with a custom thumb.

- **Do:** Wrap overflowing content inside a region that has a bounded size (a fixed height, `max-h`, or a flex child that can shrink); `orientation="horizontal"` or `"both"` for wide content like a card rail or a data grid
- **Don't:** Full-page scrolling — let the document scroll natively; Rely on it to create the size constraint; it fills its parent, so the parent must set the height/width
- **Exports:** ScrollArea

#### Spacer

A token-only spacing element with two modes: a flexible spacer that grows to fill free space along the parent flex axis, and a fixed spacer that inserts a rigid, non-collapsing gap. It renders a `div` by default and is polymorphic via `render`. It carries no visual styling and exposes no…

- **Do:** A flexible `Spacer` inside a `Stack` or flex row to push a group of items to the opposite edge (title left, actions right) without hand-tuning margins; A fixed `Spacer` when a hard gap is needed between two blocks and the container's `gap` cannot express it (e.g. one larger break in an otherwise even rhythm)
- **Don't:** Reach for `Spacer` where `Stack`'s `gap` already spaces children evenly — that is the preferred tool for consistent rhythm; Add page margins; use `Container` / `Box` for structural layout
- **Exports:** Spacer

#### Stack

A one-dimensional flex container that auto-spaces its children along a single axis. `Stack` is built on the `Box` primitive and exposes ergonomic `direction` / `gap` / `align` / `justify` / `wrap` variants so layout rhythm stays consistent and token-driven instead of hand-written `flex` utilities.

- **Do:** `Stack` for vertical form fields, button rows, list items, or any linear arrangement that needs even spacing; Switch `direction` to `row` for horizontal toolbars and metric rows
- **Don't:** `Stack` for two-dimensional layouts — reach for `Grid`; Nest deep chains of single-child stacks; compose one `Stack` per axis
- **Exports:** Stack, stackVariants

#### StaggerContainer

Reveals a set of children in sequence — each entering a beat after the last — so a list, grid, or card row cascades into view instead of appearing all at once. It composes Scroll Reveal per child, inheriting the viewport trigger, directional slide, and automatic reduced-motion fallback.

- **Do:** Card rows, feature lists, and dashboard tiles; Keep `stagger` small (60–120ms) so the cascade feels crisp
- **Don't:** Wrap large virtualised lists — the compounding delay becomes long
- **Composes with:** ScrollReveal
- **Exports:** StaggerContainer

The container for a chat transcript — a vertical `log` of Message Bubble turns. It owns the transcript semantics (a labelled `role="log"` region with an optional polite live region for streamed replies) and the rhythm between turns (a tokened gap). Each turn's alignment and colour stay with the…

- **Do:** Lay out an assistant/user conversation, a support chat, or any turn-by-turn transcript; Set `live="polite"` when assistant replies stream in, so new turns are announced
- **Don't:** A single message — render a Message Bubble directly; A general vertical stack — that is Stack
- **Exports:** ConversationThread, conversationThreadVariants

#### MessageBubble

A single turn in a conversation — a user prompt, an assistant reply, or a system note. It aligns and colours itself by `author`, so a chat transcript reads at a glance, and it announces the speaker to assistive technology.

- **Do:** `user` for the person's turns, `assistant` for replies, and `system` for inline notes (session started, context added); Keep one message per bubble
- **Don't:** Encode the speaker only through side or colour — the built-in spoken label handles that; keep it; Put interactive controls (feedback, tool calls) inside the text; place them as siblings around the bubble
- **Exports:** MessageBubble, messageBubbleVariants

#### PromptComposer

The message input for a chat or assistant surface: an auto-growing multi-line field in the AEGIS Input shell, with a send button, an optional leading action slot (attach, tools), an optional character counter, and Enter-to-send. It is the composing counterpart to the Conversation Thread and Message…

- **Do:** The input row of a chat, assistant panel, or comment box where a message is composed and sent; Provide a `label` — it is the input's accessible name (there is no visible label by design)
- **Don't:** Single-line search or form fields; reach for Search Input or Text Field. The composer is for free-form messages that may span lines; Put unrelated form controls in the toolbar; keep it to composing actions (attach, send)
- **Composes with:** Button
- **Exports:** PromptComposer, promptComposerVariants

#### ReasoningTrace

A collapsible disclosure for a model's intermediate reasoning ("chain of thought"). It stays collapsed behind a summary so it never competes with the final answer, and expands to reveal the steps on demand. It composes the AEGIS Accordion, inheriting its keyboard support, ARIA wiring, and…

- **Do:** Reveal a model's steps, tool-selection rationale, or plan; Keep it collapsed by default so the answer leads; Set `status="thinking"` while the trace is still streaming
- **Don't:** A tool invocation's inputs/outputs — that is Tool Call Block. Don't use it for generic FAQ disclosure — that is Accordion
- **Composes with:** Accordion
- **Exports:** ReasoningTrace

#### ResponseFeedback

A thumbs-up / thumbs-down control for rating an assistant response. It is a single-choice toggle: pick a rating, switch to the other, or press the active one again to clear it.

- **Do:** Place it beneath or beside an assistant Message Bubble; Treat `null` (cleared) as "no rating given"
- **Don't:** Multi-point ratings — reach for Rating (stars); Rely on colour alone to show the choice; the pressed state is also exposed via `aria-pressed` and the buttons keep their labels
- **Exports:** ResponseFeedback, feedbackButtonVariants

#### SuggestionChips

A wrapping row of tappable prompt starters or quick replies for a conversational surface — "Summarise findings", "Show critical assets", "Draft a remediation". Each chip is the interactive sibling of Tag: the same compact chip silhouette, but a real `<button>` that fires `onSelect` and carries the…

- **Do:** Offer 2–6 suggested prompts or quick replies beneath a composer or an assistant turn, to lower the cost of the next action; Keep labels short and action-oriented
- **Don't:** Display non-interactive metadata — that is Tag; A single primary action — that is a Button
- **Exports:** SuggestionChips, SuggestionChip, suggestionChipVariants

#### ToolCallBlock

A structured record of a single tool / function invocation made by an agent — the tool name, the arguments it was called with, the result it returned, and the call's status. Arguments and result render through the AEGIS Code Block (monospace, copyable, scrollable) and status through a Badge, so the…

- **Do:** Render a function/tool call in a conversation or run log; Pass `args` / `result` as objects — they're pretty-printed as JSON; Set `status="pending"` while the call is in flight
- **Don't:** The model's prose reasoning — that is Reasoning Trace. Don't use it for a plain snippet — that is Code Block
- **Composes with:** Badge, CodeBlock
- **Exports:** ToolCallBlock, toSource

#### UsageTokenMeter

A readout of how much of a bounded budget has been consumed — LLM context tokens against a window, monthly spend against a quota, requests against a rate limit. It composes the AEGIS Progress bar with a labelled header, a `used / limit` readout, and a percentage, escalating the bar's tone as usage…

- **Do:** Any consumed-vs-ceiling quantity (tokens, spend, requests, storage); Tune `warnAt` / `criticalAt` to the risk profile of the budget; Pass a `formatValue` for currency or custom units
- **Don't:** Indeterminate progress (a running task) — that is Progress with `value={null}`, or Upload Progress
- **Composes with:** Progress
- **Exports:** UsageTokenMeter

- **Do:** It in developer/settings surfaces to manage API keys; Pass a non-secret `prefix` for a recognisable masked display; Handle `onRevoke(id)` to delete the key server-side

#### AttackSurfaceWidget

A dashboard tile that summarises the exposed attack surface as a column chart — exposed services by type, open ports by category, or findings by severity across a period. It composes the AEGIS Card framing with the config-driven Bar Chart, adding a title, an optional description, and an optional…

- **Do:** Categorical exposure breakdowns on an ASM dashboard; Pass a `total` for the headline count the chart breaks down; Choose `stacked` for part-of-whole categories, grouped for comparisons
- **Don't:** Time-series remediation flow — that is Remediation Velocity. Don't use it for a bare chart — that is Bar Chart
- **Composes with:** BarChart, Card
- **Exports:** AttackSurfaceWidget

#### CveReferenceChip

A compact, scannable reference to a single CVE identifier (e.g. `CVE-2024-3094`). It is the CVE-scoped sibling of Badge: it renders the ID in a monospace face, optionally colours it by `severity` using the AEGIS `--sev-*` ramp, and — by default — links out to the canonical NVD record.

- **Do:** It wherever a CVE identifier appears as a reference; Pass `severity` when known so the chip matches the finding's severity colour; Pass `href` to point at an internal detail route; omit it to link to NVD, or pass `href={null}` for a non-interactive chip
- **Don't:** Non-CVE identifiers (CWE, GHSA) — use a plain Tag, or extend the domain set
- **Composes with:** Badge
- **Exports:** CveReferenceChip, nvdUrl

#### SslCertExpiryWidget

A compact readout of how long a TLS certificate has left before it expires. It composes the AEGIS Radial Gauge (`shape="ring"`) — the ring depletes as the remaining days fall through the validity window — with a centre "N days" readout, a humanised status line, and the certificate's host.

- **Do:** It on certificate dashboards and asset detail panes; Pass `daysRemaining` (negative = already expired); Tune `warnDays` / `criticalDays` and `windowDays` to your policy
- **Don't:** A generic countdown — this is TLS-expiry specific
- **Composes with:** RadialGauge
- **Exports:** SslCertExpiryWidget

#### AttachmentChip

A compact, inline chip that stands in for an attached file — a kind glyph, the file name, an optional size, and an optional dismiss button. It shares the AEGIS chip language with `Tag` but is file-aware: it derives its icon from the file name or MIME type through `@/lib/file`, so the same file…

- **Don't:** Put multiple interactive controls inside the chip beyond the single dismiss button; richer actions belong on a File Card; Rely on the glyph to convey the file type to assistive tech — the name (with extension) is the source of truth; the glyph is decorative

- **Don't:** Hide primary navigation, critical settings, or long-form content in a carousel; low slides beyond the first are rarely seen; Autoplay content users need to read or act on. Reserve `autoPlay` for ambient, non-essential rotation, and always pair it with `loop`

- **Exports:** Carousel, CarouselContent, CarouselItem, CarouselPrevious, CarouselNext, CarouselDots

#### ClickOutside

#### CopyToClipboard

A one-tap control for copying a value — a code snippet, an API key, an ID, a share link — to the clipboard, plus the `useCopyToClipboard` hook that powers it. On success the button briefly swaps its glyph to a check (`animate-check-pop`) and flips its accessible label to "Copied", so the…

#### ErrorBoundary

- **Don't:** Rely on it to catch errors in event handlers, async callbacks, or `setTimeout` — those aren't render-phase; handle them with `try/catch` and your own state; Wrap the entire app in a single boundary if a finer-grained one keeps more of the UI alive

#### FloatingActionButton

A prominent, circular (or extended) action pinned above the content — the primary action on a mobile or focused surface. It is built on the same Base UI Button primitive as the AEGIS Button, and the `primary` variant carries the signature accent beam, so tokens, focus ring, and motion match the…

#### FocusTrap

The "keep keyboard focus inside this region" primitive, for the custom modal surfaces you build yourself — a hand-rolled dialog, a command panel, a takeover menu — that don't already sit on a Base UI overlay. It ships as a hook (`useFocusTrap`) and a thin closed wrapper (`FocusTrap`).

- **Do:** It around custom modal content so `Tab` / `Shift+Tab` cannot reach the inert page behind it; Gate it with `enabled` so it only traps while the surface is open; Pair it with `Portal` (to escape clipping ancestors) and an `aria-modal="true"` / `role="dialog"` host for full modal semantics

#### KeyboardShortcut

Renders a key chord from a combo string as a row of `Kbd` chips — `keys="Mod+K"` becomes ⌘ K on macOS and Ctrl K elsewhere. It resolves the platform "meta" key, maps common named keys to their glyphs, and pairs the visible symbols with a spelled-out, screen-reader-only label.

#### LandmarkRegions

Thin semantic wrappers that give a page its ARIA landmark skeleton, so screen-reader and keyboard users can jump straight to the part they want. Each component renders the correct native element — meaning the landmark role is implicit and robust — and exposes a `label` where a name is needed to…

- **Don't:** Render more than one `Main` per page; Nest a `<header>`/`<footer>` inside `<main>`/`<article>`/`<section>` expecting a banner/contentinfo landmark — those roles only apply at the top level. Use `Region` for a named area inside content

#### LazyLoader

Defers rendering its children until it scrolls near the viewport, so heavy content (charts, images, embeds, long lists) doesn't cost anything until it's about to be seen. It reserves space with a placeholder to prevent layout shift, then swaps in the real content.

- **Do:** Wrap expensive, below-the-fold content; Set `minHeight` to reserve space and avoid layout shift; Pass a meaningful `placeholder` (e.g. a Skeleton) for long loads
- **Don't:** Wrap content that must be present for SEO/print — it may not render until scrolled into view
- **Exports:** LazyLoader

#### LiveRegion

#### VisuallyHidden
