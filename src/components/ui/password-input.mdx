# Password Input

A single-line secret input with a show/hide reveal toggle. It is the credential
sibling of **Text Field** and **Number Input**, sharing the AEGIS Input shell
(resting `border-strong`, `accent-strong` hover border, 3px `accent-soft` focus
ring, and the 32 / 40 / 48px size scale) so password fields sit consistently in a
form.

## When to use

- **Do** use it wherever a password or other masked secret is entered — sign-in,
  sign-up, change-password, API secrets.
- **Do** pair it with a **Password Strength Meter** on account-creation flows.
- **Don't** use it for one-time codes or PINs that benefit from per-digit boxes;
  use an **OTP Input**.
- **Don't** rely on the reveal toggle as a security feature — it only aids typing
  accuracy.

## Anatomy

1. **Label** _(optional)_ — persistent field name above the control.
2. **Shell** — the bordered container (`border-strong`) holding the parts.
3. **Input** — the masked value (`type=password`, or `text` while revealed).
4. **Reveal toggle** — the trailing eye button that shows/hides the value.
5. **Helper / error** — guidance below; swaps to a danger message when `error`
   is set.

## Sizes

| `size` | Height |
| --- | --- |
| `sm` | 32px |
| `md` | 40px (default) |
| `lg` | 48px |

## States

Default, hover (`accent-strong` border), focus-within (3px `accent-soft` ring +
accent border), disabled, and error (danger border + message). The reveal toggle
has its own hover/focus states and reflects `aria-pressed`.

## Behavior

- **Controlled**: pass `value` + `onChange`. **Uncontrolled**: pass
  `defaultValue`. It is a standard `input`, so all native input props apply.
- The reveal toggle swaps `type` between `password` and `text`. It is removed from
  the tab order (`tabIndex=-1`) so keyboard users tab straight from the field to
  the next control; it remains clickable and screen-reader labelled.
- `autoComplete` defaults to `current-password`; set `new-password` on
  account-creation forms.
- `hideReveal` removes the toggle entirely (e.g. for a numeric PIN).

## Accessibility

- The label is associated via `htmlFor`; helper/error text is linked through
  `aria-describedby` and the control carries `aria-invalid` when `error` is set.
- The toggle exposes an `aria-label` that reflects its action ("Show password" /
  "Hide password") and `aria-pressed` for its state.
- Focus is a 3px `accent-soft` ring meeting WCAG 2.2 focus appearance in both
  themes.

## API

`PasswordInput` — renders a labelled `input` with a reveal toggle.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` / `defaultValue` | `string` | — | Controlled / uncontrolled value. |
| `onChange` | `(event) => void` | — | Native input change handler. |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | Control height. |
| `label` | `ReactNode` | — | Field label. |
| `description` | `ReactNode` | — | Helper text. |
| `error` | `ReactNode` | — | Validation message + error styling. |
| `placeholder` | `string` | — | Empty-state hint. |
| `hideReveal` | `boolean` | `false` | Hide the show/hide toggle. |
| `autoComplete` | `string` | `"current-password"` | Autofill hint. |
| `disabled` / `required` / `readOnly` | `boolean` | `false` | Field flags. |
| `name` | `string` | — | Form field name. |

The public API is closed: there is no `className` or `style` prop.
