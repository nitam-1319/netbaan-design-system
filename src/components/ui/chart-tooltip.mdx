# Chart Tooltip

The floating readout that shows the values under the pointer or focus on a
chart: an optional header (the x category or point label) and one row per
series — a colour swatch, the series name, and its value. It reads the resolved
series from the shared `ChartContainer` context, so passing just a series `key`
fills in the matching colour and label automatically.

## Overview

Chart Tooltip is the tooltip **surface** — a controlled, presentational card.
Positioning and hover/focus tracking against the SVG marks are the chart's
responsibility (and are verified in a browser in CI). Keeping the surface
separate lets it be built and verified deterministically here, without a browser
runner, and reused by every chart type.

## Usage

- **Do** render it inside a `ChartContainer` so series `key`s resolve to colours
  and labels.
- **Do** pass a `key` per row to inherit the series identity; override `label`,
  `value`, or `colorVar` when needed.
- **Do** position it in a portalled floating layer that the chart drives from
  pointer/focus events.
- **Don't** treat the tooltip as the only accessible representation of the data
  — hover-only content is not reachable by every user; pair the chart with a
  text or table alternative.

## Anatomy

A `role="tooltip"` surface (`data-slot="chart-tooltip"`) mirroring the AEGIS
Popover. Inside: an optional `chart-tooltip-label` header and a `role="list"` of
`chart-tooltip-item` rows, each an `aria-hidden` swatch (series chart token) +
label + right-aligned `chart-tooltip-value`.

## Variants

| Prop | Values | Purpose |
| --- | --- | --- |
| `size` | `sm`, `md` (default) | Padding and text scale. |
| `indicator` | `dot` (default), `square`, `line` | Swatch glyph — match the mark. |

## Behavior

- Each row resolves its colour and label from the container series when a `key`
  is given; explicit `label` / `colorVar` win over the series values.
- A row with no `key` and no `colorVar` renders without a swatch (useful for
  summary rows like totals or rates).
- The surface is `pointer-events-none` so it never intercepts the pointer that
  is driving it.

## Accessibility

- Meaning never rests on colour alone (WCAG 1.4.1): each row pairs the swatch
  with a text label and a value; the swatch is `aria-hidden`.
- The card uses `role="tooltip"`. Because hover/focus tooltips are supplementary,
  ensure the underlying values are also available in a persistent, keyboard- and
  screen-reader-accessible form (e.g. a data table).
- Surface colours use the popover tokens and meet AA contrast in both themes.

## Design tokens

| Token / utility | Role |
| --- | --- |
| `bg-popover` / `text-popover-foreground` | Surface fill and text. |
| `ring-border-strong` | Surface hairline ring. |
| `shadow-elevated` | Elevation. |
| `--color-chart-1` … `--color-chart-5` | Row swatch colour (via series `colorVar`). |
| `text-muted-foreground` / `text-foreground` | Row label / value + header. |

The public API accepts no `className` or `style`; the per-row swatch colour is
applied through the series CSS variable internally.

## API

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `ReactNode` | — | Header (x category / point label). |
| `items` | `ChartTooltipItem[]` | — | One row per series. |
| `size` | `"sm" \| "md"` | `"md"` | Padding/text scale. |
| `indicator` | `"dot" \| "square" \| "line"` | `"dot"` | Swatch glyph. |

`ChartTooltipItem` = `{ key?: string; label?: ReactNode; value: ReactNode;
colorVar?: string }`.

The API is closed: `className` and `style` are not accepted.
