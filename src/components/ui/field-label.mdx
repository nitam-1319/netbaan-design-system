# Field Label

A standalone, context-free form label, exported as `Label`. It renders a
`<label>` element and associates with a control through the native `htmlFor`
prop. Reach for it whenever you lay a field out by hand — a checkbox row, a
control inside a `Box` / `Stack`, or a custom composite — and want consistent
label typography, a required / optional indicator, and disabled dimming.

## `Label` vs `FormField`'s `FieldLabel`

`FormField` (built on the Base UI `Field` primitive) exposes a `FieldLabel`
part that is **bound to the field context** — it auto-wires `htmlFor` and the
disabled state to the field's control, and you never pass `htmlFor` yourself.

`Label` (this atom) carries **no context**. You associate it explicitly via
`htmlFor`, and you own the layout. They are siblings, not duplicates: use
`FormField` when you want the wiring done for you, and `Label` when you are
composing a field the wrapper doesn't cover. See `.agent/DECISIONS.md`.

## When to use

- **Do** pair every input, textarea, select, checkbox, radio, and switch with a
  visible label, associated by `htmlFor` → the control's `id`.
- **Do** use `required` / `optional` to set expectations before submission.
- **Don't** use it as a section heading — use a heading element.
- **Don't** rely on placeholder text as a substitute for a label.

## Anatomy

The label text, optionally followed by a **required** indicator (`*` plus an
sr-only "(required)") or an **optional** hint ("(optional)"). Only one indicator
shows; `required` wins if both are set.

## Sizes

| `size` | Text |
| --- | --- |
| `sm` | 0.8rem |
| `md` | 0.875rem (default) |
| `lg` | 1rem |

Match the label size to the control it labels.

## Behavior

- Renders a `<label>` by default; swap the element with the `render` prop
  (Base UI `useRender`) for composition — e.g. render a `<legend>` inside a
  fieldset. `render` is composition, not a styling hatch.
- Clicking the label focuses / toggles the associated control (native `<label>`
  behaviour) when `htmlFor` points at a control `id`.

## Accessibility

- Always set `htmlFor` to the control's `id` so the accessible name is
  programmatically associated (WCAG 1.3.1, 4.1.2).
- The required state is conveyed in **text** — the `*` is `aria-hidden` and an
  sr-only "(required)" is announced — so meaning never depends on colour alone
  (WCAG 1.4.1). Also set `aria-required` / `required` on the control itself.
- `disabled` only dims the label; disable the control separately.

## Design tokens

| Token | Applies to |
| --- | --- |
| `--foreground` | Label text |
| `--muted-foreground` | "(optional)" hint |
| `--destructive-ink` | Required `*` indicator |

## API

`Label` — renders a `<label>` element (polymorphic via `render`).

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | Label text size. |
| `required` | `boolean` | `false` | Show a `*` indicator + sr-only "(required)". |
| `optional` | `boolean` | `false` | Show a muted "(optional)" hint. |
| `disabled` | `boolean` | `false` | Dim the label to match a disabled control. |
| `render` | `ReactElement` | `<label />` | Element to render (composition). |
| `children` | `ReactNode` | — | The label text. |

Standard `<label>` attributes (`htmlFor`, `id`, …) pass through. The public API
is closed: there is no `className` or `style` prop.
