# Password Strength Meter

A live readout of how strong a password is, built on the AEGIS **Progress** bar.
Pass the password string via `value`; a deterministic, dependency-free estimator
grades it on a 0–4 scale and the bar's fill, tone, and text label update
together. An optional requirements checklist shows which rules are still unmet.

## When to use

- **Do** place it directly beneath a password field on sign-up and
  change-password flows, so feedback appears as the user types.
- **Do** pair it with the requirements checklist when your policy has concrete
  rules — it turns a vague "weak" into an actionable list.
- **Don't** treat the score as a security guarantee. The estimator is a coarse
  UX heuristic (length + character-class variety); real policy must be enforced
  server-side.
- **Don't** block submission on the meter alone — combine it with validation.

## Anatomy

A caption + strength **label** row sits above a token-toned **Progress** bar.
Below it, an optional **requirements** list pairs a met/unmet marker with each
rule.

## Scoring

`estimatePasswordStrength(password)` returns `{ score, empty, classes, length }`.
The score is computed from length thresholds (≥ 8, ≥ 12) and how many character
classes (lowercase, uppercase, digit, symbol) appear. Passwords shorter than 6
characters are pinned to the weakest level.

| `score` | Label | Tone |
| --- | --- | --- |
| 0 | Very weak | `critical` |
| 1 | Weak | `critical` |
| 2 | Fair | `warning` |
| 3 | Good | `accent` |
| 4 | Strong | `success` |

The bar shows a sliver even at the weakest non-empty level so it always reads as
live; an empty password shows `0%` and an em-dash label.

## API

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `value` | `string` | — | Required. The password to grade. |
| `score` | `0–4` | derived | Override the computed score. |
| `size` | `sm \| md` | `md` | |
| `showLabel` | `boolean` | `true` | Show the textual strength label. |
| `labels` | `string[]` | English set | Five entries, weakest → strongest. |
| `showRequirements` | `boolean` | `false` | Show the default checklist. |
| `requirements` | `{ label, met }[]` | derived | Override the checklist. |

Exports the pure helpers `estimatePasswordStrength` and
`defaultPasswordRequirements` for reuse in form logic.

## Behavior

The component is fully controlled: it derives everything from `value` on each
render, so wire it to your password input's state. It renders no input of its
own.

## Accessibility

- The Progress bar carries `role="progressbar"` with `aria-valuenow` and an
  accessible name of "Password strength".
- The strength label is an `aria-live="polite"` region, so changes are announced
  without stealing focus.
- Requirement rows never rely on colour alone — each marker pairs a check/minus
  glyph with visually-hidden "(met)" / "(not met)" text.
- All text and markers meet WCAG 2.2 AA contrast in both themes (token colours
  over token surfaces).

## Internationalization / RTL

Provide translated `labels` and `requirements`; the layout mirrors under
`dir="rtl"` because it uses logical flex direction.

## Tokens

Fill tone comes from Progress (`accent-fill`, `bg-success`, `bg-warning`,
`bg-sev-critical`); labels use `text-destructive`, `text-warning`,
`text-accent-strong`, `text-success`; requirement markers use `bg-success/15`
and `bg-surface-3`. No hard-coded colour.
